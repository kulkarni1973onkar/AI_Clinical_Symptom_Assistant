# Medical Note Assistant 🩺

A local-first chatbot that reads clinical notes and prescriptions, identifies
medications, conditions, and symptoms, gathers context from public medical
sources, and explains everything in plain language — all without any external
LLM API.

> ⚠️ **This is not medical advice.** See [DISCLAIMER.md](DISCLAIMER.md).

## What it does

1. **Upload** a clinical note or prescription as `.txt`, `.pdf`, or an image
   (`.png`, `.jpg`, etc.). Images and scanned PDFs are OCR'd automatically.
2. **Section extraction** with [SecTag](https://www.vumc.org/cqs/sectag) — the
   note is split into clinical sections (Subjective, Medications, Plan, …).
3. **Entity extraction** with [spaCy](https://spacy.io) — finds medications,
   conditions, and symptoms using a curated keyword list.
4. **Evidence retrieval** from public medical sources, no API keys:
   [MedlinePlus](https://medlineplus.gov/) (US National Library of Medicine),
   Wikipedia, and DuckDuckGo.
5. **Plain-language analysis** generated by a local LLM via
   [Ollama](https://ollama.com) and [LangChain](https://www.langchain.com),
   grounded in the retrieved evidence.
6. **Follow-up chat** — ask questions about your document and get streamed
   answers.

## Setup

### 1. Install Ollama and pull a model

Download Ollama from <https://ollama.com>, then in a terminal:

```bash
ollama serve            # in one terminal — leave running
ollama pull llama3.2    # in another terminal — one-time download
```

### 2. Install Python dependencies

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m spacy download en_core_web_sm
```

### 3. (Optional) Install OS-level OCR support

Only needed if you'll upload images or scanned PDFs.

| OS      | Command                                                    |
|---------|------------------------------------------------------------|
| macOS   | `brew install tesseract poppler`                           |
| Ubuntu  | `sudo apt install tesseract-ocr poppler-utils`             |
| Windows | [Tesseract installer](https://github.com/UB-Mannheim/tesseract/wiki) + [poppler binaries](https://github.com/oschwartz10612/poppler-windows/releases/) |

### 4. Run the chatbot

```bash
streamlit run app.py
```

The app opens at <http://localhost:8501>. Upload one of the included samples
(`ClinicalNotes/sample_70.txt`) to try it out.

## Configuration

Settings are exposed in the Streamlit sidebar:

- **Ollama model** — defaults to `llama3.2`. Any model you've pulled with
  `ollama pull` works (`llama3.2:1b` is a good low-RAM choice).
- **Ollama base URL** — leave blank for the default `http://localhost:11434`.
  Useful if Ollama is on another machine.
- **Max entities to research** — caps the number of detected medications /
  conditions / symptoms that are looked up online. Set to 0 to disable web
  retrieval entirely (fully offline mode).

## Extending it

Most customizations live in two places:

| Want to...                                  | Edit                              |
|---------------------------------------------|-----------------------------------|
| Add a new symptom / condition / medication  | `pipeline/extractor.py` (term lists at the top) |
| Add a new evidence source                   | `pipeline/web_search.py` (add a `search_X` function and call it from `lookup_term`) |
| Change the analysis style or guardrails     | `pipeline/llm_chain.py` (`SYSTEM_PROMPT`, `ANALYSIS_PROMPT`) |
| Surface a different clinical section in the UI | `pipeline/sectag_utils.py` (`DISPLAY_SECTIONS`) |

## What changed from the original notebook

The original `OllamaMain.ipynb` used deprecated LangChain APIs and was a
linear script. The new pipeline keeps the same core ideas but:

- Replaces `langchain.llms.Ollama` with `langchain_ollama.ChatOllama`.
- Replaces `LLMChain(...).run(...)` with the modern LCEL `prompt | llm | parser`
  pattern and `.invoke()` / `.stream()`.
- Wraps section extraction in importable helpers (`extract_section`,
  `structured_summary`).
- Extends entity extraction beyond symptoms to include medications and
  conditions.
- Adds a chatbot UI, file upload (PDF/image OCR), web evidence retrieval,
  and a hardened safety prompt.

The Present/Absent symptom classifier is still available as
`pipeline.classify_symptom`.

## Limitations

- Keyword-based extraction misses terms not in the lists and can produce
  false positives.
- LLM output may contain inaccuracies. Always verify with a clinician.
- DuckDuckGo and Wikipedia are best-effort; rate-limits and outages happen.
- SecTag depends on standard headers; very free-form notes may not section
  cleanly.
